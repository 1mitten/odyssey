## How to run this queue

Take the top row whose status is `open` and whose **depends on** rows are all `done`, write `claimed <agent> <UTC time>` in its status cell, and work on a branch `claude/oq-NN-<slug>` cut from the current `claude/m1-world`. Commit small, one concern per commit, with the fast tier green after every commit (`scripts/test-fast.sh`) and, on the Windows machine, the Unity gate green before the merge (`scripts/unity.sh test editmode`, about 37 s, results file is the verdict); then `git merge --no-ff` the branch into `claude/m1-world`, never into `main`, never with `--force`, and write `done <sha>` in the status cell in that same merge. Two lanes may run at once — one code row and one research row — because a research row touches only its own file under `docs/research/`; two code rows never run concurrently, and rows that share a file are chained by **depends on** so the chain is the lock. Never touch the owner's live presentation files (`OdysseyBootstrap.cs`, `PlayScene.cs`, `ChunkRenderer.cs`, `ChunkMesher.cs`, `ModuleCatalogue.*`, `Play.unity`), never commit `Assets/Synty/`, `Library/`, `TestResults/` or logs, and if `scripts/unity.sh` reports a live editor on this project skip the **W** rows and take a **C** row instead.

**Environment tags.** **C** — a container with the dotnet 8 SDK and no Unity; the fast tier runs every Sim test (`scripts/test-fast.sh`, `--filter TestCategory=Long` for the slow ones). **C+py** — as C, and python3 is present, so `tools/wiki/build_wiki.py --check` can run; the Windows machine has no Python and its `python3` stub exits 0 doing nothing (`lessons.md`), so any row that adds player-visible content is C+py only. **W** — the Windows dev machine with Unity 6000.3.24f1; the only place the authoritative gate, editor tooling and Presentation tests run. **Web** — needs web search; rimworldwiki.com and steamcommunity.com are blocked by the remote container's egress proxy, so Lane A and Lane B rows run on W or on a container with open egress.

**Check `git status` before claiming anything.** If the working tree holds modified or untracked files you did not create, another session is live on this checkout: do not stash them, do not commit them, and take only rows that touch none of them. At the time of writing a parallel session had uncommitted work on `Sim/Pawns/ColonyWorld.cs`, `Tests/Sim/HeadlessRunTests.cs`, `Assets/Editor/Odyssey/OneDay.cs` and the bootstrap; OQ-04 and OQ-11 are written around it.

**Status cells** hold exactly one of `open`, `claimed <agent> <time>`, `done <sha>`, `blocked: <one line>`. An agent edits its own row and nothing else in this file. A row that fails is not a wasted night: write the failing seed, tick and message in the status cell, and if the failure is a bug in someone else's unit, add a row at the end of the queue for it rather than fixing it in passing.

**Every C row** commits on the fast tier. The next **W** row (and OQ-13 and OQ-21 in particular) begins by running the Unity gate on the merged `claude/m1-world`; if it is red, the row that turned it red is reopened with the failure message before any new work starts.
